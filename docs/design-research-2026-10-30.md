# 作品集设计调研与实施建议

日期：2026-10-30。范围：设计参考、内容编排与验收建议；本文件不是已实施或已上线的声明。

## 目标与已有约束

访问者需要在第一屏知道黄明清做什么，在一次滚动后看到最强的真实成果，并能读懂每件作品的具体贡献。惊喜来自作品本身、呈现节奏与可操作的细节。保留现有“展开作品”方向、薄荷底色 / 墨绿文字和已确认的 Reelmark 曲面窗口；不为增加新鲜感重新替换首屏几何。继续遵守 React + Vite + TypeScript、静态数据、/portfolio-pdf/ 子路径、PDF 独立入口、所有圆角使用超椭圆的约束。

此次阅读了 HANDOFF.MD、development-guidelines.md、homepage-design.md、App.tsx、projects.ts 和 styles.css。现有不足是：首屏已有独特性，但往下只有八条文字索引；详情主要依赖整页 PDF 图，仓库中的真实产品结构、决策和独立作品尚未展开。

## 已核验的参考

### 1. MotionSites / Reelmark V2

来源：[Reelmark V2](https://motionsites.ai/?prompt=reelmark-v2)。本次网页 HTTP 200；原作视频观察与几何参数已有 2026-10-28 项目记录，此次没有重新逐帧复测。

采用：把作品缩略图放进具有空间关系的连续展台，交互自身展示细节能力。维持 170×280 中央窗口、196 节距、50 单位/秒和独立边高等已有要求。新项目只更新内容，不改变体验的核心识别点。

不采用：他人的产品视频、登录注册元素、来源不明的营销成绩。没有本人演示视频时使用真实截图。

### 2. Framer Marketplace / Vertical

来源：[Vertical 官方模板页](https://www.framer.com/marketplace/templates/vertical/)，作者 Tamas Bodo；官方页面标注 2026-09-30 更新。[预览](https://vertical.framer.media/) 本次 HTTP 200。参考的是页面公开描述的设计方法，未购买或复制模板代码与素材；未宣称逐像素视觉审核。

采用：内容优先、清晰网格、大幅真实图像、强标题与有节奏的阅读路径。在本项目中，先做三件精选作品的展开版，再让其余作品进入精简档案，避免每个项目都挤进同一种卡片。

### 3. Maria Vasilyeva Portfolio / 作者在 Codrops 的案例

来源：[作者与开发者的案例文章，2026-10-20](https://tympanus.net/codrops/2026/10/20/maria-vasilyeva-portfolio/)，[CSS Design Awards 官方页面](https://www.cssdesignawards.com/sites/maria-vasilyeva-portfolio/50006/)。后者确认该站获得 2026-09-03 Website Of The Day；本次不采用无法直接复核的其他平台评分。

采用：一个与个人相关的隐喻贯穿布局和交互；不同段落可以有不同视觉密度，动态展示之后安排安静的阅读区。本站的共同语言已经是“展开”，无需另换音乐或游戏隐喻。让精选案例更像打开一张工作台，关于区则收敛为清晰文字。

不采用：音效、全站 WebGL 文字、复杂加载序列和多重图像变形。本项目的核心是产品与工具的可信展示，并已有严格首屏预算。

### 4. Awwwards 官方评审方式

来源：[Evaluation System](https://www.awwwards.com/about-evaluation/)。网页工具请求超时后，通过只读 HTTP 请求获得 200，并核验页面正文列出的四项权重：Design 40%、Usability 30%、Creativity 20%、Content 10%。

采用：美感、可用性、创意与内容一起验收。设计完成不能仅看首屏截图；点击进入、阅读案例、移动端、键盘和加载都属于最终作品。

这些权重是平台公开规则，不是本站已获分数，也不意味着采用本建议会获得奖项。

### 5. Framer 官方排版与无障碍准则

来源：[Using text styles](https://www.framer.com/help/articles/how-to-use-text-styles/)、[Accessibility](https://www.framer.com/help/accessibility/)、[Troubleshooting animation issues](https://www.framer.com/help/articles/troubleshooting-animation-issues/)。

采用：复用排版样式；语义标题、图片替代文本、明确链接名称、合理 Tab 顺序、可读对比度和减少动态效果。新加的动画只增强呈现，不能让用户等待动画才能读取内容，也不能在减少动态效果模式下禁用手动切换。

## 本项目的建议结构

1. 首屏：保留主标题、曲面展台、PDF 与浏览作品入口。把 rail 素材升级为最有识别度的真实项目截图，确保每个窗口的中心裁切能读出产品类型。
2. 精选案例：三件作品；首件用宽幅界面作为整段焦点，后两件用不同图文比例形成节奏。每件只保留作品名、一句问题与实现、类别和进入入口。大图不加成段解释性覆盖文字。
3. 项目档案：所有经过核验的独立项目，以文字行呈现；可采用少量分类筛选。数量来源于真实数据，不把 fork、镜像、资料备份计为原创项目。分类名称应直接表达产品、自动化、创意实践或研究，不堆技术栈标签。
4. 关于：一句明确的工作取向，加一段有证据的实践概括。只使用现有文档可证明的履历与联系方式；保持 GitHub 与 PDF 入口。
5. 案例弹窗：项目名与一句定位 → 主图 → 面向谁 / 什么问题 → 关键决策与实现 → 本人角色与范围 → 结果与已知边界 → 更多截图或演示 → 相邻项目。移动端正文应可直接阅读，PDF 全页图仅作为补充。

三件精选优先从实际素材中选择，建议覆盖“沉浸式产品体验”“业务自动化”“AI 洞察 / 创意工具”三类。最终名单由仓库证据质量、截图可读性和独立贡献清晰度决定，而不是仓库更新时间或代码量。

## 可直接实施的视觉约束

- 保留底色 #F5F8EF、墨绿 #08482D、正文 #101410；作品图保持原色。若使用深绿大段落，只用于一次明确的篇章转换，不能将页面变成拼贴色块。
- 继续使用本地 Inter Tight 与中文系统字体。H2 约 36–44px、案例标题 28–36px、正文 15–17px；移动端按可读性缩放，不能一并缩成截图上的微小字。
- 内容最大宽度约 1240px，桌面左右 40px / 4% 基础边距，移动端约 6%。纵向留白表达段落层级；不要用额外说明行解释每个区域。
- 产品图优先使用 16:10 或原生宽高比；图内完整 UI 不应强行 cover 裁掉导航或关键流程。曲面 rail 缩略图可单独选择裁切。
- 三件精选在画幅与布局上变化，但使用相同标题、类别和链接样式。不要重复三次“左文右图”的整齐模板，也不要用十几个浮动窗口掩盖产品主图。
- hover 采用轻微位移、颜色变化或图片放大，键盘焦点同等可见。核心功能不能依赖 hover。滚动入场最多短距离 transform + opacity，不加滚动劫持。
- 所有按钮、媒体框与弹窗遵循超椭圆；保持原有不支持 corner-shape 时的降级方案。无需圆角的图可以直角，不能偷偷回退到普通圆角。

## 生成图与真实素材的边界

优先使用用户仓库内真实产品图和视频。生成图适合制作统一的项目封面气氛图、纸艺旅行场景、工作台插画等，但不能当作真实产品界面或工作成果的证据。凡是生成或重绘的示意图，在案例中用简短图注说明。涉及客户或内部业务数据的截图先筛选；用已有演示数据素材优于仓促遮盖。原图中的真实产品标题、代码与细节不可随意改写成不存在的功能。

## 验收清单

- 内容：每件作品可追溯到仓库文件；项目状态、本人贡献、原创 / 复刻和演示性质准确；无空白详情、无虚构指标、无“即将上线”占位。
- 首屏：1440×1080 与 1366×768 看得到主要信息及浏览入口；曲面窗口维持已确认几何；新图在裁切后仍可辨识。
- 响应式：390×844、320×740 与宽屏无横向溢出；正文与控制可读可点；大图可合理查看细节。
- 交互：所有精选、档案、筛选、PDF、外链与案例切换有效；Esc / Tab 循环 / 焦点恢复有效；拖动不误开项目。
- 动效：显式暂停、减少动态效果、页面隐藏与离屏暂停仍有效；新增案例切换不会积累 RAF、计时器或媒体解码实例。
- 资源：首屏不请求 PDF / 完整视频 / 全部案例大图；图片声明尺寸，按需加载；首屏目标 ≤900KB，JS gzip ≤100KB，CSS gzip ≤15KB。
- 性能：构建与类型检查通过；实际浏览器记录资源、控制台、CLS 和首屏结果。不得将本地测量写成线上、微信或 iOS 真机验证。
- 交付：保留原站与 PDF 直链，明确本地 / 已发布状态；HANDOFF.MD 与部署状态记录实际完成的检查及未验证项。

## 调研限制

本轮完成公开页面与作者说明核验，没有对每个参考站逐一进行移动端或键盘交互测试。设计建议为结合本站约束的判断，不宣称平台官方建议必须采用这些具体布局。Awwwards 与 MotionSites 的 HTTP 可达性不等于完整浏览器渲染验收。
